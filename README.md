# NeuroMedicine — ітеративне зжимання нейромереж для скринінгу очного дна

Програма реалізує алгоритм з «Інструкцій для зжимання» (В. Кисіль): згорткова мережа
отримує досвід від VGG-16, донавчається до повноти ~100 %, а потім цикл за циклом
«зганяє» досвід з частини нейронів, фізично їх вирізає й дотреновується. Цикл триває, доки мережа
не почне «фейлити», і тоді результатом стає мережа з попередньої ітерації.

Один рушій зжимання обслуговує дві моделі, разом вони утворюють конвеєр скринінгу:

| Модель | Вхід | Вихід | Конфігурація |
|---|---|---|---|
| **Сегментатор диска зорового нерва** (VGG-16 → U-Net-подібний декодер) | знімок очного дна, 1×288² (сірий після CLAHE) | маска диска | `configs/segmentation.yaml` |
| **Класифікатор кропу диска** (VGG-16 → GAP → FC) | кроп навколо диска, 3×128² | `glaucoma` (підозра на глаукому), `valid_image` (чи це справді диск) | `configs/classifier.yaml` |

Основою слугували: інструкція, чернетка статті («Article worksheet ua») та вихідний код
[retinal-stuff-stremalined](https://github.com/vovannn012347/retinal-stuff-stremalined): попередня обробка
(HSV-S + CLAHE у LAB), архітектура, метрики, k-fold, буфер складних зразків.

> ⚠️ Це дослідницький інструмент, а не медичний виріб. Результати не є діагнозом.

## Алгоритм і де він у коді

| Крок інструкції | Реалізація | Параметри |
|---|---|---|
| 1. Трансплантуємо перші 4 блоки VGG-16 | `neuromed/models/transfer.py`: ваги ImageNet копіюються в 10 згорток кодувальника. Для сірого входу фільтри першого шару сумуються за RGB, для вужчої мережі беруться фільтри з найбільшою нормою | `model.pretrained`, `model.base` |
| 2. Донавчаємо, щоб встановились зв'язки вищих рівнів | перші епохи трансплантовані шари заморожені, далі навчається вся мережа | `train.freeze_transferred_epochs` |
| 3. Тренуємо до «достатніх показників» (повнота ~100 %) | `PhaseMonitor`: ціль, терпіння, найкраща епоха | `train.target`, `train.selection`, `train.patience` |
| 4.1 dropout 0.1–0.2 → 0.5 | фаза `spread`: досвід розноситься на кілька нейронів | `compress.spread_epochs`, `dropout_start`, `dropout_max` |
| 4.2 нормування ваг нейронів, які будуть вирізані | вибір каналів з найменшою L2-нормою (`planning.py`), групова норма їхніх фільтрів, bias і вхідних ваг наступних шарів (`regularizer.py`) | `compress.prune_ratio`, `importance`, `norm_include_consumers` |
| 4.3 одночасно dropout 0.5 → 0 і частка нормування 0 → 0.95 | фаза `squeeze`: `L = (1 − α)·L_задачі + α·R`, а норма вирізуваних ваг обмежена `(1 − α)` від початкової | `compress.squeeze_epochs`, `norm_max`, `norm_method` |
| 4.4 вирізаємо нейрони, далі менший крок | `surgery.py` будує нову, вужчу модель і переносить ваги; крок навчання ×0.5 | `compress.lr_scale_after_cut`, `min_lr` |
| 4.5 дотреновуємо, поки показники не стабілізуються | фаза `stabilize` з монітором | `compress.stabilize_*` |
| 4.6 повторюємо, поки мережа не почне фейлити; тоді беремо попередню | критерії прийняття відносно ітерації 0. Після провалу — повтор від попередньої мережі з удвічі меншою часткою, а коли зменшувати вже нікуди, зупинка | `compress.acceptance`, `retry_smaller_ratio`, `min_prune_ratio` |

Ширини шарів зберігаються в чекпойнті (`arch.widths`), тож стиснена модель відтворюється
точно. Тест перевіряє, що вирізання дає той самий вихід, що й обнулення вирізаних нейронів.

**Режими нормування** (`compress.norm_method`):

- `penalty` — лише штраф у функції втрат;
- `projection` — лише жорстке обмеження норми після кожного кроку;
- `both` (типово) — штраф м'яко переносить знання, обмеження гарантує, що на момент вирізання
  у вирізуваних вагах лишається ≤ 5 % норми. Тоді вирізання майже не змінює передбачень.
  Сам по собі штраф за короткі фази лишав 60–70 % норми.

**Додатково зі статті:**

- k-fold: навчання на k−1 частинах, контроль втрат на частині, що лишилась (`data.epoch_strategy: kfold`).
  Є й варіант з інструкції, де мережа вчиться по черзі на непересічних частинах (`alternate`).
- Буфер найскладніших зразків розміром до 1 фолду, зважений повтор (`data.hard_examples`).
- Аугментація на GPU: поворот, скошення, масштаб, віддзеркалення, яскравість, контраст, гамма,
  розмиття, шум, плями-артефакти (`data.augment`).
- «Крайні випадки»: найскладніші правильно розпізнані тестові зразки ітерації 0. На кожній ітерації
  метрика `edge_detected` показує, яка їхня частка ще розпізнається.
- Дистиляція знань (необов'язково, `distill.enabled`): вчителем стає ітерація 0.

## Встановлення

Потрібні Python 3.10+ (перевірено на 3.14) і, бажано, відеокарта NVIDIA (перевірено на RTX 4050 Laptop, 6 ГБ).

```bash
python -m venv .venv
```

```bash
.venv\Scripts\activate
```

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130
```

```bash
pip install -r requirements.txt
```

Без GPU досить останньої команди: стане CPU-збірка PyTorch, і все працюватиме, лише повільніше.
Під час першого запуску з `model.pretrained: true` torchvision завантажить ваги VGG-16 ImageNet
(528 МБ, `download.pytorch.org`) у кеш `~/.cache/torch`.

### PyCharm

1. **Settings → Project → Python Interpreter → Add Interpreter → Existing** і вкажіть `.venv\Scripts\python.exe`.
2. У списку конфігурацій запуску (праворуч угорі) вже є готові: підготовка даних, швидка перевірка,
   зжимання обох моделей, продовження перерваного запуску, скринінг і тести. Вони лежать у `.idea/runConfigurations/`.
3. Теки `data/` і `runs/` виключені з індексації: там тисячі зображень і чекпойнти.

|---|---|---|---|---|
| PAPILA | маски диска від двох експертів, діагноз (здоровий / глаукома / підозра) | 488 / 853 | GPL-3.0 | [figshare 10.6084/m9.figshare.14798004](https://doi.org/10.6084/m9.figshare.14798004) |
| ACRIMA | готові кропи диска з мітками глаукоми | — / 705 | CC BY 4.0 | [figshare 10.6084/m9.figshare.7613135](https://doi.org/10.6084/m9.figshare.7613135) |
| Fundus DG (REFUGE, Drishti-GS, ORIGA, RIGA) | маски диска з 6 доменів, мітки глаукоми REFUGE | 1441 / 1441 | CC BY 4.0 | [zenodo 8009107](https://zenodo.org/records/8009107) |

Розпакуйте архіви в `data/raw/papila`, `data/raw/acrima`, `data/raw/zenodo_dg` (структура всередині
довільна: потрібні теки знаходяться автоматично) і перетворіть їх у єдиний формат:

```bash
python -m neuromed prepare all
```

Результат буде в `data/processed/<датасет>/`:

- `images/`, `masks/` (квадрат 576²);
- `crops/` (кропи диска 256² і «невалідні» кропи поза диском);
- `segmentation.csv`, `classification.csv`, `meta.json`.

Мітки, яких немає, записуються як −1 і не входять у втрати й метрики. Для класифікатора на кожен знімок
додається кроп поза диском з `valid_image = 0`: так класифікатор вчиться відкидати хибні виявлення сегментатора.

PAPILA-«підозри» за замовчуванням невідомі (`--suspect-as unknown`), можна вказати `positive` або `negative`.
Розбиття на train/val/test групується за пацієнтом (обидва ока — в одній вибірці) і стратифікується за джерелом і міткою.

Без завантажень можна перевірити весь конвеєр на синтетичних знімках:

```bash
python -m neuromed prepare synthetic
```

## Запуск

```bash
python -m neuromed compress --config configs/smoke_synthetic.yaml
```

Це швидка перевірка, хвилина-дві навіть на CPU. Повні запуски:

```bash
python -m neuromed compress --config configs/segmentation.yaml
```

```bash
python -m neuromed compress --config configs/classifier.yaml
```

Інші режими:

| Що | Команда |
|---|---|
| продовжити перерваний запуск | `python -m neuromed compress -c configs/segmentation.yaml --resume` |
| лише ітерація 0, стиснення пізніше | `python -m neuromed train -c configs/segmentation.yaml`, потім `compress ... --resume` |
| стиснути готову мережу | `python -m neuromed compress -c configs/segmentation.yaml --baseline шлях/до/iter00.pt` |
| змінити параметр без редагування YAML | `--set compress.prune_ratio=0.25 --set name=seg_r25` |
| метрики чекпойнта | `python -m neuromed evaluate --checkpoint runs/segmentation/checkpoints/final.pt --split test` |
| порівняльна таблиця кількох чекпойнтів | `python -m neuromed benchmark --checkpoints a.pt b.pt c.pt --out runs/benchmark` |
| опис чекпойнта | `python -m neuromed info --checkpoint runs/classifier/checkpoints/final.pt` |
| скринінг знімків | `python -m neuromed predict --seg runs/segmentation/checkpoints/final.pt --cls runs/classifier/checkpoints/final.pt --input теки/зі/знімками --out runs/predictions` |

Скринінг виконує повний ланцюжок:

1. обрізає знімок до кола очного дна;
2. сегментує диск;
3. для кожного виявлення вирізає кроп і класифікує його.

На виході: `results.json`, `results.csv`, маски, накладки з контуром і рамками, кропи.

### Що лишається після запуску (`runs/<name>/`)

| Файл | Зміст |
|---|---|
| `log.txt` | журнал: кожна епоха з dropout, часткою нормування α, залишковою нормою ‖w‖ і метриками |
| `history.csv` | те саме таблицею, по рядку на епоху всіх фаз |
| `checkpoints/iterNN_xW.pt` | мережа після ітерації NN (W — ширина першого шару). Відхилені ітерації мають суфікс `_rejected` |
| `checkpoints/final.pt` | результат: остання прийнята ітерація |
| `report.md`, `report.csv` | таблиця як у статті: параметри, розмір, час інференсу на CPU, метрики на тесті, епохи, час навчання |
| `compression_curve.png` | якість і час інференсу залежно від кількості параметрів |
| `state.json`, `splits.json`, `config.yaml` | стан для `--resume`, точне розбиття даних, повна конфігурація |

### Метрики

Пороги класифікатора калібруються на контрольній вибірці (`eval.calibrate_recall`, напр. повнота 95 % для глаукоми)
і застосовуються до тестової.

- **Сегментатор.** Головна метрика — виявлення диска: компонента маски з IoU ≥ 0.2 з еталоном.
  - `det_recall`, `det_precision`, `det_f1`;
  - `det_tp`, `det_fn`;
  - `extra_detections` (хибні виявлення);
  - `n_predictions`;
  - маска: `dice`, `iou`, `pix_precision`, `pix_recall`, `pix_f1`, `pix_accuracy`.
- **Класифікатор.** Для кожної мітки:
  - `<мітка>_recall`, `_precision`, `_specificity`, `_f1`, `_f2`, `_accuracy`, `_auc`;
  - `_tp`, `_fp`, `_fn`, `_tn`, `_threshold`;
  - а також `mean_auc`.
- `edge_detected` — частка «крайніх випадків», які ще розпізнаються.

## Конфігурація

Усі параметри з типовими значеннями описано в `neuromed/config.py`. Невідомий ключ у YAML дає помилку,
тож друкарські помилки не пройдуть непоміченими. Найважливіші параметри:

| Ключ | Значення |
|---|---|
| `data.input_size` | сторона входу (кратна 16) |
| `data.epoch_strategy` | `kfold` / `alternate` / `full` |
| `data.preprocess.grayscale` | сірий вхід (сегментатор) чи кольоровий (класифікатор: блідість диска важлива) |
| `model.base` | ширина першого шару: 64 = повна VGG-16, 32/16/8 — вужчі |
| `train.target` | «достатні показники» для ітерації 0, напр. `{det_recall: 0.99, dice: 0.85}` |
| `compress.prune_ratio` | частка нейронів, що вирізається за ітерацію (0.5: 64 → 32 → 16 → 8) |
| `compress.acceptance.minimum` | абсолютні мінімуми, нижче яких мережа «фейлить» |
| `compress.acceptance.max_drop` | допустиме падіння відносно ітерації 0 |
| `compress.norm_method` | `both` / `penalty` / `projection` |
| `distill.enabled` | дистиляція від ітерації 0 |
| `train.amp`, `train.channels_last` | змішана точність і формат NHWC на CUDA (≈20 % швидше) |

## Тести

```bash
python -m pytest
```

55 тестів, близько 10 секунд на CPU:

- вирізання еквівалентне обнуленню нейронів (обидві моделі, кілька ітерацій поспіль);
- чекпойнти стисненої моделі відтворюються точно;
- нормування: штраф і обмеження;
- розклади фаз і монітор;
- метрики (ROC AUC через попарне порівняння, виявлення диска);
- конфігурація, попередня обробка, аугментація, розбиття;
- наскрізні запуски `train` → `compress --resume` → `evaluate`/`benchmark`/`predict` та класифікатор з дистиляцією
  на крихітному синтетичному датасеті.

## Структура

```
neuromed/
  cli.py                 командний рядок
  config.py              YAML → перевірені dataclass-и
  models/                VGG-блоки, сегментатор, класифікатор, трансплантація VGG-16
  compression/           специфікація вирізання, вибір нейронів, нормування, хірургія, розклади, цикл зжимання
  data/                  підготовка датасетів, попередня обробка, аугментація, розбиття, буфер складних зразків
  training/              функції втрат, метрики, монітор фаз, тренер, чекпойнти
  evaluation/            швидкість на CPU, звіт (таблиця + графік)
  inference/predict.py   конвеєр скринінгу
configs/                 segmentation.yaml, classifier.yaml, smoke_synthetic.yaml
tests/                   pytest
```

### Відмінності від вихідного коду

- **Ширина шарів у чекпойнті.** Вихідний код після вирізання «латає» шари на місці. Тут модель будується
  заново з описом ширин, тож будь-яку ітерацію можна завантажити без вихідної мережі.
- **Числова стабільність.** BCE рахується з логітів, тренування у змішаній точності.
- **Швидкість.** Дані й аугментація тримаються на GPU, а не в DataLoader: у Windows воркери повільні.
- **Обидві задачі в одному рушії.** Сегментатор і класифікатор спільно використовують рушій, метрики й звіти.

### Обмеження

- Мітки глаукоми з різних датасетів зібрані за різними протоколами. ACRIMA містить лише готові кропи.
- Розмір мережі вимірюється параметрами, мегабайтами ваг і часом інференсу на CPU (4 потоки). Квантизація та
  інші методи стиснення свідомо не входять: за постановкою досліджується саме вирізання нейронів.
